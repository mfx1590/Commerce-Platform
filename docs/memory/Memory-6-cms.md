## Decisions made (with reasons)
- **One document per BCP-47 locale, `(type, locale, slug)` unique** (accepted by the manager 2026-09-08). The storefront routes `/[locale]/…` with next-intl and renders one language per request; a document per locale maps 1:1 onto that URL, GROQ filters `locale == $locale`, a missing translation is a missing document (not a half-translated page), and it mirrors `store_locale` (row per locale). Field-level i18n would fight the route tree. Uniqueness is a Studio-side query (`uniqueLocaleSlug`); ids are deterministic `<type>.<locale>.<slug>` (`documentId`) so seeds re-run and a translation is the same id with another locale. Window 10 adds de-DE by cloning fixtures (README "Adding a locale").
- **`sanity` is a devDependency for the Studio only; `src/**` types schemas against a local structural mirror (`src/schema/define.ts`).** The storefront imports the built `dist/` and must not pull the Studio; CI neither. `sanity.config.ts` casts `schemaTypes` to Sanity's union (the mirror is structural, not discriminated) and `test/sanity-compile.test.ts` compiles the registry with Sanity's own `createSchema` — proven non-vacuous (a bogus type yields `error: Unknown type`).
- **Validation is data the tests can run.** `RecordingRule` (immutable like Sanity's Rule) records the chain; `validateDocument` walks fields/named types/arrays. Sanity enforces validation only in the Studio, so this is what the seed, fixtures and later the fetch-layer tests rely on.
- **Datasets = `store.code` = `store.content_space_id`** (`brand-a|b|c`), environments are further datasets (`brand-a-staging` when needed). Private datasets; the storefront reads server-side only.
- **Links are storefront paths or http(s) only** (`uri({allowRelative, scheme})`): `javascript:`/`mailto:` rejected at the schema. Product stories carry a kebab-case handle, never a price (ADR 0004).
- **2.2: plain-`fetch` GROQ client, no `@sanity/client`** (same reasoning as `store-api`): one module knows URLs/token, `fetchImpl` injectable, Next's data cache does the caching (`next: { tags, revalidate: 300 }` published via `apicdn`, `cache: 'no-store'` + bearer + `perspective=drafts` via `api` for preview). GROQ params travel as `$name=<json>`, never interpolated. Reads never throw: unconfigured/unknown store → empty + one warn per process; failed request → empty + one warn with status + `x-sanity-request-id`.
- **2.2: preview cookie = `<exp>.<HMAC-SHA256(SANITY_PREVIEW_SECRET, "<dataset>|<exp>")>`**, httpOnly/Lax/Secure(prod)/2 h; `/api/cms/preview?secret&redirect` (503 without secret+read token, 401 wrong secret, same-site redirect only), `/api/cms/preview/exit`. Webhook `/api/cms/revalidate`: Sanity's `sanity-webhook-signature: t=<ms>,v1=<base64url hmac("<t>.<body>")>`, 5-min tolerance, constant-time; tags `cms` / `cms:<type>` / `cms:<type>:<locale>:<slug|key>`; unknown type still drops `cms`; 503 without secret (never trust an unverifiable webhook). Handlers are pure `Request → Response` in `src/lib/cms/handlers.ts`; `route.ts` files are one-liners (hq-rbac lesson: mounted, not just exported).
- **2.3: `(content)` gets its own CMS-fed header and footer** (`src/lib/cms/components/{navigation,footer}.tsx`, static links / copyright as fallback) instead of editing window 3's `src/layouts/defaults.tsx`; the shop adopts them in wave C, mount points named in REQUEST #178 (manager-confirmed 2026-09-08). Same for `HomeContent` (page slug `home`, renders nothing when unpublished).
- **2.3: strings via `createTranslator` from next-intl over `src/lib/cms/messages/<locale>.json`** (`content` namespace, own parity + hard-coded-string tests) — window 3 owns `messages/*.json` and `src/i18n/request.ts`; #178 merges the namespace app-wide later but nothing depends on it. Fallback: exact locale → same language → en-GB.
- **2.3: one `<h1>` per page** — the hero headline when a page has a hero, the title otherwise; heroes inside block lists are `<h2>`; portable text allows h2/h3 only. Tested (no skipped heading levels). Images: plain `<img>` from the asset ref (`cdn.sanity.io/images/<pid>/<dataset>/<id>-<w>x<h>.<fmt>`) with alt/width/height/lazy; `next.config` `remotePatterns` (window 3) lacks `cdn.sanity.io`, so no `next/image` until 2.5's Cloudinary loader. No `generateStaticParams` (build runs with no CMS; pages cache by tag).
- **2.4: srcdoc embeds never get `allow-same-origin`** — a `srcdoc` iframe inherits the parent's origin, so with `allow-scripts` that flag would hand a pasted snippet the whole page (cookies, DOM). Provider frames (Builder/Framer, cross-origin) keep it because "same origin" is then the provider's own. Constants `SRCDOC_SANDBOX` / `PROVIDER_SANDBOX` in `components/embed.tsx`, asserted per provider in tests; `allow=""`, lazy, strict referrer policy, height clamped.
- **2.4: embed URLs are allow-listed twice** — `isAllowedEmbedUrl` (https only, no userinfo, wildcard = exactly one subdomain label) runs in the schema validator AND again at render; a stored document that fails renders nothing. Embeds exist only on `campaignLanding.blocks` (`campaignBlocks`), not on pages.
- **2.4: renderers never trust stored hrefs** (#193 review): every CMS href goes through `safeHref()`/`SafeLink` — internal path → locale Link, `https://` → `rel="noopener noreferrer"`, anything else → plain `<span>`. Campaign pages 404 outside `startsAt`/`endsAt` (`campaignIsLive`, fail-closed on garbage dates, `now` injectable). UTM passthrough proven by running window 3's real middleware on a campaign URL (a `NextRequest` works under Vitest) and reading the `sf_attribution` cookie.
- **2.3: nits from #163 landed in cms 0.2.0** — `uniqueLocaleKey` (navigation.key) / `uniqueLocale` (footer.locale) via a shared `uniqueWithin()`; `HREF_PATTERN = /^(?:\/(?!\/)|https:\/\/[^\s/?#]+)/` replaces `uri({allowRelative})`.
- **Seed via Sanity's HTTP API from a `.mjs` runner over the built `dist/`** (no `@sanity/client` dep, no tsx): uploads a 1×1 PNG placeholder and rewrites fixture asset refs, because Sanity rejects strong references to missing assets. ## Gotchas learned
- Integration 1 (2026-09-08): real Keycloak staff tokens are the default on the core's Admin API; `CORE_DEV_TOKENS=1` keeps `Bearer dev:<subject>` working locally. The storefront can run against the core with `STORE_API_URL=http://localhost:9000` (+ `CORE_STORE_API_FALLBACK=1` + `CORE_STORE_API_FALLBACK_URL=http://localhost:4010` on the core so unimplemented Store routes still answer from Prism). The admin uses `ADMIN_API_URL`.

- `sanity schema validate` (CLI) cannot load our config: its esbuild-register loader does not map NodeNext `.js` specifiers to `.ts`. The Studio itself (`sanity dev`, Vite) does. Hence the compile test instead of a CLI script.
- Sanity's CLI only passes `SANITY_STUDIO_*` env vars to the config; `scripts/studio.mjs` maps `SANITY_PROJECT_ID` from the root `.env` onto `SANITY_STUDIO_PROJECT_ID`.
- **Ownership is narrower than it looks:** `apps/storefront-starter/test/**`, `package.json`, `README.md`, `CHANGELOG.md`, `vitest.config.ts` are all window 3's — only `(content)/**`, `api/cms/**`, `lib/cms/**` (and `test/cms-*` once the request lands) are mine. Storefront-side docs go in `src/lib/cms/README.md`; storefront deps via REQUEST. Before committing anything under a new path run `OWNERSHIP_BRANCH=cms/phase2 OWNERSHIP_FILES=$'<paths>' bash scripts/check-ownership.sh` (test mode, no commit needed).
- JSDoc: a path glob like `api/cms/*/route.ts` inside a `/** … */` comment ends the comment (`*/`) — TS1443 "Module declaration names…" is the symptom.
- Next page files may export only the route API (`default`, `generateMetadata`, …): a helper exported from `page.tsx` breaks the build — put it in `src/lib/cms/*.ts`.
- next-intl types `createTranslator` keys against the app's augmented message shape; a wrapper taking `key: string` needs a cast (`t as unknown as ContentTranslator`). `createTranslator` IS exported from `next-intl` (verified at runtime), so a namespace can live outside `messages/*.json`.
- eslint `consistent-type-imports` forbids `importOriginal<typeof import('…')>()` in `vi.mock` — declare `import type * as Mod from '…'` at the top instead.
- Testing RSC trees without a DOM: `test/cms-render.ts` calls function components (sync or async) recursively and returns `{tag, props, children}`; `Link` from `@/i18n/navigation` is mocked as `'a'` and `next/navigation`'s `notFound` as a throwing stub.
- Bash tool: a `cd` inside one call persists into later calls (and into background jobs started afterwards) — always `cd /c/Users/mehdi/Desktop/wt-cms &&` or use absolute paths.
- `exactOptionalPropertyTypes`: `{ ...obj, validation: undefined }` is a type error; destructure the key away instead.

## How to run & test this package
- `pnpm --filter @platform/cms typecheck` (src + tests, then `tsconfig.studio.json` with `sanity.config.ts`), `pnpm --filter @platform/cms test` (Vitest, 35 tests), `pnpm --filter @platform/cms build` (dist for the storefront), `pnpm lint`, `pnpm format:check` (cms/** is prettier-checked; run `pnpm exec prettier --write cms`).
- Studio: `pnpm --filter @platform/cms studio` (needs `SANITY_PROJECT_ID` in `.env`); seed: `pnpm --filter @platform/cms seed -- --dataset brand-a|all` (needs `SANITY_WRITE_TOKEN`; prints manual steps otherwise).
