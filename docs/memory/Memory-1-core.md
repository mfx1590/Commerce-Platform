## Decisions made (with reasons)
- 2026-09-14 · **Order markers come in pairs**: `marker(client, …)` opens its own transaction; `markerInTx(tx, …)` runs on the caller's. Window 8's shipment insert holds `FOR KEY SHARE` on the order row, so a marker on a second connection deadlocks — the InTx twins are the supported way to combine a shipment write with an order transition (#191).
- 2026-09-14 · **`VoidInput`/`RefundInput` carry the store** (window 7's gap): on the placement failure path the transaction is being rolled back, so a provider must resolve per-store PSP credentials from `storeId`, never from `tx`.
- 2026-09-09 · **Abandoned carts: idle = `updated_at` older than the threshold; reactivation by any mutation resets the clock; a new abandonment is a new event** (manager, 2.6). The job never touches `updated_at` (it stays the customer's last activity, carried as `last_activity_at`); empty carts are never abandoned; `SKIP LOCKED` makes concurrent runs safe.
- 2026-09-09 · **The job is a Medusa scheduled job** (`src/jobs/abandoned-carts.ts`: `export const config = { name, schedule }` + `export default`), so it runs in-process under `MEDUSA_WORKER_MODE = shared | worker` with no extra scheduler; the same function is a CLI for runbooks. Medusa's job loader validates EVERY file in `src/jobs` (throws "Config is required for scheduled jobs" otherwise) — window 9's `index-products.ts` there is a plain CLI → **REQUEST #201** (verified from Medusa's source: `validateConfig` throws unless the file exports `config` + `default` or the `MEDUSA_SKIP_FILE` marker); confirm on the first `pnpm --filter @platform/core dev` boot once the stack is back.
- 2026-09-09 · **#191 answered with adapters, not renames**: window 8's port shapes (`setFulfillmentStatus`, `consumeReservations`, `releaseReservations` by order line item and per shipment) are thin wrappers over the 2.3/2.4 functions; idempotency per shipment comes from the movement references (`shipment` / `shipment_release`), no schema change. - Adding an event to `completeCart`'s `withEvents` changes every test that lists the order's outbox topics (checkout.test.ts asserts the sorted topic list) — update the expectation, do not filter the query.
- Module-level wrappers that open `client.transaction` must never be called from inside another module's transaction on the same rows: expose a `…In(tx, …)` variant instead (orders does for the returns module).

- The shared docker stack disappeared mid-task (no `commerce-platform-*` containers at all, port 5433 closed): DB tests and the server boot cannot run until the manager restarts it (`pnpm dev` at a quiet moment) — never recreate it from a window. Work that needs no DB (typecheck, lint, docs) continues.
- A background gate run's summary is lost when the command pipes through `head`: capture the full log to a file and grep the summary afterwards.
- Positions in `product_media` are renumbered by first parking a moved row at a large position so the (product, position) rewrite never collides mid-way.

- `app.set_updated_at()` (migration 0001) is a BEFORE UPDATE trigger on every table: a test cannot backdate `updated_at` with an UPDATE — drive time-based logic through an injected clock instead (the abandoned-cart tests pass `now` in the future). The trigger also bumps `updated_at` when the job flips a cart to `abandoned` (harmless: abandoned carts are never reselected).
- Seeded stock per (variant, warehouse) is < 40 (EU) / < 20 (US): a fixture demanding `available >= 50` in one warehouse selects nothing and the suite fails in `beforeAll` with "Cannot read properties of undefined" (3 skipped, no ×) — pick thresholds the seed can satisfy.
- Test keys / fixtures stay words-only (the repo is public since 2026-09-14): no real-looking API keys or secrets even as placeholders.
