# Domain model (frozen with contracts-v0.1)

Expands plan section 3. Every window uses these names, verbatim, in SQL, OpenAPI, events, and UI.
Source of truth for the schema is `packages/db/migrations`; this document explains it and names the owner.

## Conventions

| Rule | Value |
|---|---|
| Identifiers | `uuid` primary keys generated by the database (`gen_random_uuid()`); the API exposes them unchanged |
| Tenancy | Every table has `organization_id uuid NOT NULL`. Store-scoped tables also have `store_id uuid NOT NULL`. RLS on both (ADR 0001) |
| Timestamps | `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL DEFAULT now()` on every mutable table |
| Money | integer minor units (`amount_minor bigint`) plus an ISO-4217 `currency char(3)`. Never floats |
| Codes | `code`/`handle`/`slug` are lowercase kebab-case, unique per store (or per organization for org-scoped tables) |
| Soft delete | none. Archive via `status`; hard deletes only through GDPR flows (window 13) |
| Audit | Every admin mutation writes `audit_log` (before/after JSON) in the same transaction |
| Events | Every state change on a starred entity in plan section 3 writes `outbox` in the same transaction (ADR 0003) |
| Naming | snake_case tables and columns, singular table names, `<table>_id` foreign keys |

Session context set by the tenant client (`packages/db`): `app.organization_id`, `app.scope` (`organization` | `store`),
`app.store_ids` (csv of uuids, used when scope is `store`), `app.actor_id`. Missing context means no rows.

## Ownership legend

Window numbers refer to `docs/memory/Memory-main.md` window index. "main" = main window (schema frozen, changes by CONTRACT CHANGE issue).
Owner means: owns the module code that mutates the entity; the schema itself is always `packages/db` (main).

### stock_item
What physically lies on a shelf (db 0.3.4, migration 0190; CONTRACT CHANGE #453). Organization-level: the brands that
map it share one stock pool. A store's `product_variant.stock_item_id` points at one item (nullable until 0191, then
mandatory); the backfill maps every variant 1:1 and never merges — pooling two brands is an explicit HQ act.

| Field | Type | Notes |
|---|---|---|
| id | uuid PK | |
| organization_id | uuid FK | |
| sku | text | unique per organization; the variant's sku when unique, else `<store code>:<sku>` |
| name | text | |
| barcode | text NULL | |

RLS kind `pool_self`: organization scope sees every item; a store-scoped session only the items one of its own
stores' variants maps. Only organization scope may map a variant (database trigger, 42501 otherwise). From 0191 the
pool's rows (`inventory_level`, `stock_movement`) are keyed by stock item; reservations stay per store.
Owner: window 11 (warehouse). Events: `stock.moved` v2 and `stock_item.mapped` v1 (events 0.3.3, landed with 0191;
the mapping writes `stock_item.mapped`).

### cycle_count
Somebody counted a stock item in a warehouse, and what became of the count (db 0.3.6, migration 0192; CONTRACT
CHANGE #458). Organization-level: it carries no `store_id`. A count never edits a level — reconciliation turns the
difference into exactly one `stock_movement` (reason `cycle_count`, no store) and links it here; that link makes a
second reconcile of the same count a no-op. A count is a record: the application role cannot delete one.

| Field | Type | Notes |
|---|---|---|
| id | uuid PK | |
| organization_id | uuid FK organization | |
| warehouse_id | uuid FK warehouse | |
| stock_item_id | uuid FK stock_item | |

| counted_by | uuid NULL FK staff_user | NOT NULL exactly when `source` is `manual` (CHECK); NULL = a system source |
| counted_at | timestamptz | when the shelf was counted (not when the row was written) |
| source | text | `manual` (default) / `wms` |
| note | text NULL | |
| status | text | `recorded` (default) / `flagged` / `applied` |
| on_hand_as_of_count | int NULL | on-hand as of `counted_at`, computed by the last reconciliation under the pool row's lock; NULL while `recorded` |
| delta | int NULL | `counted_quantity − on_hand_as_of_count` (CHECK); NULL while `recorded` |
| stock_movement_id | uuid NULL UNIQUE FK stock_movement | set exactly when a non-zero delta was applied (CHECK) |
| approved_by | uuid NULL FK staff_user | with `approved_at`, only on an `applied` count (CHECK) |
| approved_at | timestamptz NULL | |
| reconciled_at | timestamptz NULL | NOT NULL once reconciled |
| created_at / updated_at | timestamptz | |

Status: `recorded` — written down, not reconciled yet; `flagged` — reconciled, the discrepancy is above
`organization.settings.warehouse.count_tolerance`: nothing moved, it waits for an approval by `operations` on
`organization:hq`; `applied` — reconciled, `stock_movement_id` is the movement (NULL only when the delta was 0).
`on_hand_as_of_count` and `delta` are final once the count is applied.

RLS kind `organization_only`: the organization's rows in organization scope ONLY — no store session reads or writes
a count, not even for an item it maps. No DELETE for `platform_app`; UPDATE stays (the row is updated as it is
reconciled).

Owner: window 11 (warehouse). Events: none of its own — reconciliation emits `stock.moved` through the inventory
module.
