## 5. The manager loop (details in the runbook; this is the shape)

1. `bash scripts/status.sh`, `gh pr list`.
2. For each open PR: spawn a **background, read-only reviewer agent** (`Agent` tool, `general-purpose`; model **fable** for anything touching auth, tenancy/RLS, the outbox, payments or contracts, **opus** otherwise). Prompt shape: repo + PR + branch; "do NOT modify files, change git state, merge or comment"; what to read first (the issue's acceptance criteria, the ADRs, the contract, the window's memory file on the branch, Memory-main gotchas and the decisions you gave that window); numbered checks with evidence (ownership; acceptance criteria item by item; invariants; tests real; CI state); "reply with exactly one first line MERGE or BLOCK, then numbered reasons, then Nits (not now)". BLOCK only on real defects or missing criteria. Re-check mechanical fixes yourself with `git show`; re-review non-mechanical ones as a diff-only review.
3. Merge only with `bash scripts/merge-queue.sh "<pr> <branch>" ["<pr> <branch>" …]` run **in the background** (10–20 min per PR): it merges `origin/main` into a detached checkout, pushes `HEAD:refs/heads/<branch>`, waits for CI (ignoring only the advisory `app images` check), merges with a **merge commit**. One queue at a time. **A running queue cannot be stopped** — never start it for a PR that must not merge yet. It refuses on red CI and on non-lockfile conflicts (then the window must merge main and resolve). After it reports: confirm with `gh pr view N --json state,mergeCommit`, `git pull --ff-only`, close the task issue **only if the state is MERGED**, tell the window.
4. Requests: root config (`.env.example`, `docs/ownership.md`, eslint/prettier, `pnpm-workspace.yaml`, `scripts/**`, ADRs) you apply on main yourself the same day, comment "Applied on main in <sha>", close. Work inside another window's paths you route in that window's next paste. Contract changes: accept if additive and consistent with `docs/domain.md`; land them **between** PRs (after the requesting window's PR merges), never during; windows keep a `proposed/` copy and apply DDL only in their tests until then, and your landing commit deletes those copies.
5. After every merge round: a new bullet at the **top** of Memory-main "Current status" (what merged with shas, what was refused and why, decisions, who is quiet), commit + push directly to main (branch protection logs an admin bypass — intended, and only for docs/memory, runbook and root-config files).
